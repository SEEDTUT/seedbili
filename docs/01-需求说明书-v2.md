# 自动回复 Agent 工具 · 需求说明书 v2

> 基于 `文档（）暂时/自动回复 Agent 工具 · 需求书（给 PC 端 Agent）`（2026-10-31, seedtut）扩写。
> 本文只写**变更点与补全点**；未提及的一律沿用原需求书。编号 FR = 功能需求，NFR = 非功能需求，AC = 验收标准。
> 两处主动偏离原文的地方用 ⚠ 标出，均已收进 `05-待确认清单.md`。

## 一、术语表（原文未定义，实现前必须先统一）

| 术语 | 定义 |
|---|---|
| 目标 | 一个可抓取的投稿对象：视频（`bvid`/`aid`）或专栏或动态。**首版只做视频**。 |
| 顶层评论 | B 站 reply 树里 `parent == 0 && root == 0` 的一条。楼中楼不是一级公民。 |
| 已回复过 | 该顶层评论下已存在任一条由「本账号」发出或「主 UP」发出的子评论。 |
| 台账 | 本地持久化的「已处理评论」集合，主键 = 评论 `rpid`。用于去重、审计、复盘。 |
| 兜底 | Agent 置信度不足或工具链出错时的退化行为：`只汇报` / `自动回复` / `直接跳过`。 |
| 汇报 | 把待人工定夺的条目写进收件箱队列，界面可见、可一键处理，不自动发送。 |
| 一轮（run） | 一次「抓取 → 过滤 → 判断 → 执行」的完整遍历。一轮内每条候选最多处理一次。 |
| 风控码 | B 站接口返回的非零 `code`，如 `12014` 发送上限、`12051` 重复评论、`-101` 未登录、`-509` 频率限制。 |

## 二、范围边界（原需求书没划，实现时最容易在这里失控）

**首版做**：单账号、单平台（B 站）、视频评论区；用户手动指定目标 + 手动触发一轮；Agent 判断 + 工具执行 + 台账去重 + 限速 + 收件箱。

**首版明确不做**（避免范围蔓延，二版再评估）：

- 定时/无人值守轮询（要接 Windows 计划任务）。
- 动态、专栏、直播间、私信。
- 多账号并发（数据模型预留 `accountId`，UI 只做单账号）。
- 自动关注/点赞/投币 —— 不属于「回复」，风控更敏感。
- **代理 IP 池、请求指纹伪装、验证码破解** —— 与需求书第九章「遵守平台规则、不做激进抓取」冲突，**永久拒绝**，不做成可配置项。

## 三、功能需求

### FR-1 平台适配层（把原第一章「插件式」要求可执行化）

- FR-1.1 `PlatformAdapter` 是接口；工作流、Agent 工具、UI 只依赖接口，业务代码里不出现 `bilibili` 字面量。
- FR-1.2 适配器经 `ServiceLoader` 发现；jar 放进 `%APPDATA%\ReplyAgent\plugins\` 即被加载。**首版就要有这套机制**，哪怕只有一个官方适配器。
- FR-1.3 接口能力：`listAccounts / loginStatus / startLogin / fetchComments / postReply / resolveTarget`。平台不具备的能力返回 `Unsupported`，不得抛异常打断工作流。
- **AC-1**：移除 B 站适配器实现、只留接口，工程仍能编译。
- **AC-2**：写一个纯内存的 `DemoAdapter` 丢进插件目录，UI 能列出它并跑通完整一轮。 ← 这是「插件化不是纸面插件化」的唯一硬证据。

### FR-2 登录（原第五章）

- FR-2.1 ⚠ **主路径改为 B 站官方扫码登录**：本地用 ZXing 生成二维码（不外传），用户手机 B 站 App 扫码，工具轮询官方接口取回登录态。
  偏离原文「内置浏览器」的理由：真正的内置浏览器引擎（JCEF ≈120MB，或 WebView2 + JNI 桥）与第九章「体积优先」直接冲突；且扫码路径**界面上根本不存在密码框**，对「工具和 Agent 都不接触密码」这条要求是超额满足而不是打折。代价：无法顺手处理图形验证码/滑块。
- FR-2.2 ⚠ **兜底路径：手动粘贴 Cookie**（`SESSDATA` + `bili_jct` + `DedeUid`），输入框为密码型、粘贴后立刻清空剪贴板选项、只落加密存储。给「不方便扫码」和「官方扫码接口变更」留退路。
- FR-2.3 登录能力暴露给 Agent 的工具粒度：`open_login`（唤起登录界面）、`check_login`（查状态）、`relogin`（失效时重新拉起）。**不存在 `fill_password` / `solve_captcha` 这类工具，接口层面就不给。**
- FR-2.4 登录成功回调进主流程：状态从 `未登录` → `已登录`，界面提示可进入下一步。
- **AC**：全程抓包看不到工具向外发送任何密码字段；日志里 cookie 只显示前 4 位 + 长度。

### FR-3 API 配置（原第四章）

- FR-3.1 字段：`name(Base URL)`、`apiKey`、`model`、`temperature`、`maxTokens`、`topP`、自定义 header、超时、`stream` 开关。
- FR-3.2 多套 profile，可切换、可复制、可设默认。
- FR-3.3 Key 存 DPAPI（`CryptProtectData`, CurrentUser 作用域），配置文件里只有密文；非 Windows 退化为机器绑定 AES-GCM。
- FR-3.4 「连通性测试」按钮，必须区分并明确报出：DNS 解析失败 / TCP 连不上 / TLS 失败 / 401 鉴权 / 404 模型名 / 429 配额 / 返回体不是 OpenAI 结构 / 超时。
- FR-3.5 工具调用（function calling）能力必须实测跑通，UI 里用一个「工具回环自检」按钮验证。
- **AC**：填一个错的模型名，界面要说「模型名不对」而不是笼统「请求失败」。

### FR-4 Agent 判断与执行（原第六章）

- FR-4.1 输入拼装：`系统人设(提示词模板)` + `策略配置渲染出的规则块` + `单条评论(标注为不可信数据)` + `可用工具 schema`。
- FR-4.2 Agent 输出只能是三种动作之一：`reply` / `skip` / `escalate`（转人工），且必须带 `confidence`。
- FR-4.3 动作通过工具调用落地：`post_reply`、`skip_comment`、`report_for_review`，外加只读工具 `fetch_comments`、`get_config`、`check_login`、（沙箱可用时）`run_command`。
- FR-4.4 循环上限：单条评论最多 N 次模型往返（默认 4），超限即降级为 `escalate`。
- FR-4.5 手动粘贴入口：用户可把任意内容贴进来跑一次判断，用于调试提示词（对应原话「把内容加上提示词换上给 agent」）。
- **AC**：一条明显无意义的评论 → `skip`；一条提问 → `reply`；一条诱导「忽略之前的规则」→ 依然按普通文本处理，不改变行为。

### FR-5 策略配置（原第七章，全部可编辑）

- FR-5.1 每一项都是配置对象，具备 `enabled` 开关 + 增删改；默认值来自需求书的表。
- FR-5.2 支持多套预设（profile）、导入/导出（单个 JSON 文件，UTF-8，可人工读改）。
- FR-5.3 渲染进提示词的规则块以配置为准；代码里不出现具体人名、具体阈值常量。
- FR-5.4 ⚠ 「指令注入防护」是唯一硬编码项，且**不提供开关**；界面在策略页固定显示一条只读说明，明确告知用户它不可关闭及原因。
- **AC**：把跳过名单清空后，Agent 不再看到「主 UP」这个概念；导出配置在另一台机器导入后行为一致。

### FR-6 台账与去重（原第七章「已处理台账」）

- 按 `rpid` 主键；记录动作、耗时、模型 token 用量、原文、回复内容、接口返回码。
- 清理周期可配（默认 180 天）。提供界面查看、按目标筛选、导出 CSV。

### FR-7 发送节奏（原第七章「发送节奏」）

- 参数：最小间隔、间隔抖动、单轮上限、单日上限、连续失败退避（指数 + 上限）、命中 `12014/-509` 时的冷却时长。
- **默认值保守**：间隔 20–45s 抖动、单日 20 条。宁慢不猛。

### FR-8 虚拟 Linux 环境（原第三章）

- FR-8.1 后端可插拔：`WSL 发行版` / `本机进程` / `无（禁用命令工具）`。默认 `无`。
- FR-8.2 探测用 `wsl -l -v` + 注册表 `HKLM\...\VirtualMachineMode`，能区分「未装 WSL」「装了但无发行版」「有发行版」三态。
- FR-8.3 命令工具 `run_command` **默认关闭**，需用户在设置里显式开启，且每条命令执行前界面弹确认（可配「本次会话内不再询问」）。理由：把 shell 交给远端模型是本项目里风险最高的面，不能靠默认开。
- FR-8.4 文件交换用工作目录（`%APPDATA%\ReplyAgent\sandbox\work`），WSL 侧经 `/mnt/d` 或 `wsl --cd` 访问；不假设用户目录结构。
- FR-8.5 一键初始化/重建/清理，清理必须删干净目录与注册痕迹。
- FR-8.6 ⚠ 本项目**不会替用户静默安装 WSL**（要管理员权限、可能重启、体积 >1GB，属于对用户机器的侵入式变更），只在界面给出可直接复制的安装命令与说明。
- **推荐路线结论**（详见架构文档第九章）：`wsl --install -d Debian`（≈200–400MB）而不是塞一整个 Ubuntu Desktop；若只要一个能跑 Python/curl 的沙箱，`Alpine`（<50MB）+ 手动补工具更贴「1GB 以内」的要求。

## 六、测试要求（原第九章「充分测试」具体化）

- 单测：策略过滤（含双重黑名单校验）、指令注入清洗、台账去重与过期、限速器时序、WBI 签名（给定固定 img_key/sub_key 与参数，断言 `w_rid` 等于已知值）、配置导入导出往返一致性。
- 契约测试：LLM 客户端用本地假 OpenAI server（JDK 内置 `HttpServer`）跑通「带工具的两次往返」。
- 冒烟：真实启动窗口，逐页可达，无异常弹窗。
- **无法自动化的部分要如实标注**：B 站真实登录与真实发评论需要用户账号，属人工验收项，不假称已测。
